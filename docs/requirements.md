# 要件定義

## 機能要件

### 初期リリース必須

| # | 機能 | 概要 |
|---|------|------|
| F-01 | DICOM 保管・閲覧 | HealthImaging への保管と OHIF Viewer による閲覧 |
| F-02 | アプリ内コード編集 | ブラウザ上での Python / MATLAB スクリプト編集 |
| F-03 | 設定ファイル入出力 | 設定ファイルのインポート / エクスポート |
| F-04 | ワークスペース分離 | `personal/` / `shared/dropbox/` / `shared/templates/` の分離 |
| F-05 | 解析ノード制御 | MATLAB ノードの起動 / 停止 / 状態確認 |
| F-06 | Python 実行環境 | JupyterLab による Python 解析実行 |
| F-07 | 実行結果保存 | `results/` への保存 |
| F-08 | 権限分離 | 管理者 / 一般利用者レベルの IAM・Cognito ロール分離 |
| F-09 | 基本監査ログ | 起動停止・画像アクセス・解析開始の操作ログ |

## 非機能要件

### セキュリティ
- IAM 最小権限原則を遵守する。
- 本番環境の IAM 権限を広く取らない。
- EC2 をユーザーが直接自由起動できる構成にしない。
- 全通信を暗号化する（TLS 1.2+）。
- Secrets は AWS Secrets Manager / SSM Parameter Store で管理する。

### 可用性・運用
- 高額な EC2 は常時起動しない（オンデマンド）。
- 停止 / 再起動でデータが消失しない設計にする。
- 少人数チームが継続運用できる複雑さに留める。

### 監査・コンプライアンス
- CloudTrail により全 API 操作を記録する。
- 主要操作（起動停止・画像アクセス・解析開始・結果保存）を追跡可能にする。

---

## 制約事項

- DICOM 正式保管は AWS HealthImaging のみとする（S3 単独代替禁止）。
- GUI 要件のある MATLAB は EC2 + DCV で実行する（Lambda / Fargate 禁止）。
- 1 か月運用後にコスト・アクセス傾向を観測し、ストレージと計算基盤を再評価する。
